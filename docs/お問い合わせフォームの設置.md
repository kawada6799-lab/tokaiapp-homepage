# お問い合わせフォームの設置と、迷惑送信対策

## 先に確認したこと

**いまのフォームは、まだ送信できません。**
`pages/contact.html` の `<form action="#">` は「どこにも送らない」という意味で、
見た目だけのひな型です。

つまり **現時点で、このサイトのフォームから迷惑メールが送られる経路はありません。**
いま届いている迷惑メールは、`info@tokaiapp.com` 宛に**直接**送られているものです。

やる順番はこうなります。

| 順 | やること | いまの状態 |
|---|---|---|
| 1 | 直接届く迷惑メールを減らす（メール側の設定） | **これが先** |
| 2 | フォームを動くようにする（Contact Form 7） | まだ |
| 3 | フォームの迷惑送信対策を入れる | 2と同時 |

---

## 1. 直接届く迷惑メールを減らす（先にこちら）

サイトの設定では止められません。ConoHa のメール側で対処します。

1. [ConoHa コントロールパネル](https://www.conoha.jp/login/) → **メール**
2. `info@tokaiapp.com` を選ぶ
3. **迷惑メール設定** を有効にする

これで多くは振り分けられます。それでも減らない場合は、
**公開用のアドレスを `info@` 以外に変える**のが最終手段です。
`info@` は総当たりで真っ先に狙われるアドレスなので、
`contact@` などにすると、それだけで大きく減ることがあります。

> サイト側では、アドレスをHTMLに直接書かない対策を済ませています。
> 新しく収集されることは防げますが、**すでに出回っているアドレスには効きません。**

---

## 2. フォームを動くようにする

### 2-1. Contact Form 7 を入れる

WordPress の **プラグイン → 新規追加** で「Contact Form 7」を検索し、
インストール → 有効化。

### 2-2. フォームを作る

**お問い合わせ → 新規追加**。タイトルは「お問い合わせ」。

**「フォーム」タブ**の中身を、すべて消して次を貼り付けてください。
サイトの見た目に合うようにクラスを指定してあります。

```
<div class="form">

  <div class="form__row">
    <label class="form__label" for="f-clinic">医院名 <span class="req">必須</span></label>
    [text* clinic id:f-clinic class:form__input]
  </div>

  <div class="form__row">
    <label class="form__label" for="f-name">お名前 <span class="req">必須</span></label>
    [text* your-name id:f-name class:form__input autocomplete:name]
  </div>

  <div class="form__row">
    <label class="form__label" for="f-email">メールアドレス <span class="req">必須</span></label>
    [email* your-email id:f-email class:form__input autocomplete:email]
  </div>

  <div class="form__row">
    <label class="form__label" for="f-tel">電話番号</label>
    [tel tel id:f-tel class:form__input autocomplete:tel]
  </div>

  <div class="form__row">
    <label class="form__label" for="f-topic">ご相談の内容</label>
    [select topic id:f-topic class:form__input "どれから始めるか相談したい" "クリニック専用アプリ" "医療DX導入支援" "ドウイナビ（検査説明DX）" "資料がほしい" "その他"]
  </div>

  <div class="form__row">
    <label class="form__label" for="f-body">お問い合わせ内容</label>
    [textarea message id:f-body class:form__input class:form__input--area rows:6]
  </div>

  <div class="form__check">
    [acceptance consent] <a href="/privacy/">プライバシーポリシー</a>に同意します [/acceptance]
  </div>

  [submit class:btn class:btn--cta class:form__submit "この内容で送信する"]

</div>
```

### 2-3. メールの設定（ここを間違えると届きません）

**「メール」タブ**を、次のように設定します。

| 項目 | 設定する値 |
|---|---|
| 送信先 | `info@tokaiapp.com` |
| **送信元** | `東海App <info@tokaiapp.com>` |
| 題名 | `[ホームページ] [clinic] 様よりお問い合わせ` |
| 追加ヘッダー | `Reply-To: [your-email]` |

> **★重要★ 送信元には、必ず自分のドメインのアドレスを入れてください。**
> ここに送信者のアドレス（`[your-email]`）を入れると、
> 「他人になりすましたメール」と判定されて**届かなくなります**。
> 送信者へ返信できるようにするのが「追加ヘッダー」の `Reply-To` です。

**メッセージ本文**:

```
ホームページのお問い合わせフォームより送信がありました。

医院名　　： [clinic]
お名前　　： [your-name]
メール　　： [your-email]
電話番号　： [tel]
ご相談内容： [topic]

--- お問い合わせ内容 ---
[message]
------------------------

送信日時： [_date] [_time]
送信元IP： [_remote_ip]
```

### 2-4. 自動返信メール（任意ですが、あると親切です）

同じ「メール」タブの下にある **「メール (2)」を使用** にチェック。

| 項目 | 設定する値 |
|---|---|
| 送信先 | `[your-email]` |
| 送信元 | `東海App <info@tokaiapp.com>` |
| 題名 | `【東海App】お問い合わせを受け付けました` |
| 追加ヘッダー | `Reply-To: info@tokaiapp.com` |

**メッセージ本文**:

```
[your-name] 様

お問い合わせをいただき、ありがとうございます。
以下の内容で received いたしました。3営業日以内に担当よりご連絡します。

医院名　　： [clinic]
ご相談内容： [topic]

--- お問い合わせ内容 ---
[message]
------------------------

※ このメールは自動送信です。ご返信いただいても対応できません。

--------------------------------
東海App
〒464-0008 愛知県名古屋市千種区宮根台
info@tokaiapp.com
https://tokaiapp.com/
--------------------------------
```

> 本文中の `received` は英語のまま残さず、「承りました」に直してください。

### 2-5. ショートコードをページに貼る

保存すると、画面上部に次のようなショートコードが出ます。

```
[contact-form-7 id="123" title="お問い合わせ"]
```

これを `pages/contact.html` の
**`<!-- ▼▼▼ ここから ▼▼▼ -->` から `<!-- ▲▲▲ ここまでを置き換える ▲▲▲ -->` の間**
（`<form>` 〜 `</form>`）と丸ごと入れ替えます。

ただし **HTMLにショートコードを書いても、そのままでは展開されません。**
次のどちらかにしてください。

- **やり方A（かんたん）**: `pages/contact.html` を削除する
  → テーマは自動で WordPress の固定ページ本文に切り替わるので、
  ブロックエディタで「お問い合わせ」ページを普通に作り、
  ショートコードを貼る
- **やり方B**: チャットで「フォームのショートコードは `[contact-form-7 id="123" …]`」と
  教えてください。テーマ側でショートコードを展開する処理を入れます

**やり方Bのほうが、いまのデザインをそのまま保てます。**

### 2-6. テストする

必ず自分で1通送って、次を確認してください。

- [ ] `info@tokaiapp.com` に届くか（**迷惑メールフォルダも見る**）
- [ ] 自動返信が送信者に届くか
- [ ] 届いたメールに「返信」して、送信者のアドレスに返るか（Reply-To の確認）

## 3. フォームの迷惑送信対策

**フォームを動かすのと同時に入れてください。** 何も入れないと、
公開した翌日から機械的な送信が始まります。

### おすすめの順番

| | 方法 | 利用者の手間 | 外部への情報送信 | プライバシーポリシーの追記 |
|---|---|---|---|---|
| **1番目** | **Honeypot** | なし | なし | **不要** |
| 2番目 | Cloudflare Turnstile | ほぼなし | あり | 必要 |
| 3番目 | reCAPTCHA v3 | なし | あり（Google） | 必要 |
| 併用 | Akismet | なし | あり | 必要 |

### まずは Honeypot（これだけで十分なことが多い）

人間には見えない入力欄をフォームに置き、そこに入力があったら弾く方式です。
**外部サービスに情報が出ないので、プライバシーポリシーを直す必要がありません。**

1. **プラグイン → 新規追加** で「Honeypot for Contact Form 7」を検索
2. インストール → 有効化
3. お問い合わせのフォーム編集画面に **[honeypot]** タグが増えるので、
   フォームの中（`</div>` の直前あたり）に次の1行を足す

```
[honeypot website-2 id:website-2 move-inline-css:on]
```

これで、フォームに自動入力してくる機械的な送信はほぼ止まります。

### それでも来るなら Turnstile を足す

Cloudflare の無料サービスです。reCAPTCHA と違い、
利用者が画像を選ばされることがほとんどありません。

1. Cloudflare にログイン → **Turnstile** → サイトを追加してキーを取得
2. Contact Form 7 の **インテグレーション** 設定にキーを入れる
3. フォームに `[turnstile]` タグを足す
4. **プライバシーポリシーに追記する**（下記）

### プライバシーポリシーへの追記

Turnstile か reCAPTCHA を入れたら、`pages/privacy.html` の
「外部サービスの利用」に次を足してください（こちらでやることもできます）。

```html
<h3>迷惑送信の防止</h3>
<p>
  <strong>Cloudflare Turnstile</strong>（Cloudflare, Inc.）<br>
  お問い合わせフォームへの機械的な送信を防ぐために利用しています。
  フォームのあるページで、閲覧者のIPアドレスと操作の情報が
  Cloudflare に送信されます。
</p>
```

reCAPTCHA の場合は提供者が Google LLC になり、
**サイト全体で動く**ため「フォームのあるページで」の部分が変わります。
