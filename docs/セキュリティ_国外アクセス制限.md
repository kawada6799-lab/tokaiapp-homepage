# 国外からのアクセスを制限する

## 先に、いちばん大事なこと

**サイト全体を国外から遮断すると、検索結果に出なくなる可能性があります。**

Googleの検索ロボット（Googlebot）は、主に**米国のIPアドレス**から
ページを読みにきます。サイト全体を「日本以外お断り」にすると、
このロボットも弾かれ、ページが検索結果に載らなくなります。

医療機関に見つけてもらうための導線が切れるので、**既定では次の形**にしています。

| | 国外から |
|---|---|
| 公開ページ（ホーム・サービス・料金など） | **通す** |
| ログイン画面 `wp-login.php` | **止める** |
| 管理画面 `wp-admin` | **止める** |
| XML-RPC `xmlrpc.php` | **止める** |
| REST API の書き込み（POST/PUT/DELETE） | **止める** |
| コメント投稿 | **止める** |
| お問い合わせフォームの送信 | 迷惑メール扱いにする |

不正ログインの試行はほぼすべてこの「止める」側に来るので、
実害はこれで大きく減らせます。

それでもサイト全体を止めたい場合は、下の「サイト全体を止める」を読んでください。

---

## 3つの層があります

止める場所は3つあり、**外側ほど効果が高い**です。

| 層 | 場所 | 効果 | 手間 |
|---|---|---|---|
| 1 | ConoHa WING の「海外アクセス制限」 | 高い（PHPが動く前に止まる） | 画面でONにするだけ |
| 2 | Cloudflare などのCDN | 最も高い（サーバーに届く前に止まる） | 設定が少し要る |
| 3 | このテーマの `inc/geo-guard.php` | 低い（WordPressは起動してしまう） | 導入済み |

**層3だけでは不十分です。** WordPressが起動したあとに弾くので、
攻撃の負荷そのものは減りません。テーマを切り替えると外れます。

**まず層1を有効にしてください。** 層3は取りこぼしの受け皿です。

---

## 層1: ConoHa WING の「海外アクセス制限」（まずこれ）

**このサイトは ConoHa WING で運用しています。** ConoHa WING には
国外からのアクセスを遮断する機能が標準で用意されています。
コントロールパネルでONにするだけです。

### 手順

1. [ConoHa のコントロールパネル](https://www.conoha.jp/login/) にログイン
2. 上部メニューの **WING**
3. 左メニューの **サイト管理**
4. 左メニューの **サイトセキュリティ**
5. 上のタブから **WordPressセキュリティ**
6. **海外アクセス制限** を開き、次の3つを **ON** にする

| 項目 | 何が止まるか | 設定 |
|---|---|---|
| ダッシュボード | 国外からの `wp-login.php` / `wp-admin` | **ON** |
| XML-RPC API | 国外からの `xmlrpc.php`（総当たり攻撃の入口） | **ON** |
| REST API | 国外からの REST API 呼び出し | **ON** |

これで**公開ページは今までどおり見られたまま**、
不正ログインの試行だけが止まります。検索への影響もありません。

> REST API を止めると、外部サービスからサイトのデータを読みにくる連携が
> 動かなくなることがあります。いまは連携していないので問題ありませんが、
> 将来なにか繋ぐときは思い出してください。

### あわせてONにしておくとよいもの

同じ **サイトセキュリティ** の画面に、次の機能もあります。

- **WAF** — よくある攻撃パターンを遮断します。ONを推奨
- **IPアクセス制限** — 特定のIPを個別に遮断・許可できます。
  攻撃元が特定できたときに使います（ブラックリスト／ホワイトリスト）

### 海外から自分が入れなくなる点に注意

この設定を入れると、**河田さんご自身も海外からは管理画面に入れません。**
VPNを使っている場合も、接続先が海外なら弾かれます。

出張などで海外から更新する必要が出たら:

1. **ConoHa のコントロールパネルは別物なので、海外からでも入れます**
2. コントロールパネルで「ダッシュボード」の項目を一時的に **OFF** にする
3. 作業が終わったら **ON** に戻す

「WordPressに入れない＝詰み」ではないので、安心してONにして構いません。

### ConoHa がカバーしない部分

ConoHa の海外アクセス制限は、上の3項目が対象です。
次はテーマ側（層3）で受け持ちます。

| | ConoHa | このテーマ |
|---|---|---|
| ログイン・管理画面 | ○ | ○ |
| XML-RPC | ○ | ○ |
| REST API | ○（全部） | ○（書き込みのみ） |
| コメント投稿 | — | ○ |
| お問い合わせフォームの送信 | — | ○（迷惑メール扱い） |
| サイト全体 | — | ○（既定は無効） |

二重に効いても害はありません。ConoHa 側が先に止めるだけです。

## 層2: Cloudflare（さらに強くしたいとき）

サーバーに届く前に止まるので、いちばん効果があります。無料プランで設定できます。

### 設定手順

1. Cloudflare のダッシュボードで tokaiapp.com を選ぶ
2. **Security → WAF → Custom rules** を開く
3. 「Create rule」で次のルールを作る

**ルール名**: 管理画面を国内限定にする

**条件（Expression）**:

```
(not ip.geoip.country in {"JP"}) and (
  http.request.uri.path contains "/wp-login.php" or
  http.request.uri.path contains "/wp-admin" or
  http.request.uri.path contains "/xmlrpc.php"
)
```

**動作（Action）**: Block

4. 保存して有効化

> `/wp-admin/admin-ajax.php` は、公開ページの機能で使われることがあります。
> 何かが動かなくなったら、条件に
> `and not http.request.uri.path contains "/admin-ajax.php"` を足してください。

### 大事な注意 — 直接アクセスを塞ぐ

Cloudflare を入れても、**サーバーのIPアドレスに直接アクセスされると素通り**します。
Cloudflare を経由しないと届かないよう、サーバー側で
**Cloudflare のIPアドレス以外からの接続を拒否**してください。

Cloudflare のIP一覧: https://www.cloudflare.com/ips/

これをやらないと、層2も層3も回避されます（下の「弱点」を参照）。

---

## 層3: このテーマの `inc/geo-guard.php`（導入済み）

テーマに組み込んであります。追加の作業は不要です。

### どうやって国を判定しているか

CDNやサーバーが付ける**国コードのヘッダ**を読んでいます。

- `CF-IPCountry`（Cloudflare）
- `CloudFront-Viewer-Country`（Amazon CloudFront）
- `X-AppEngine-Country`（Google Cloud）
- `GeoIP-Country-Code`（Apache / nginx の GeoIPモジュール）
- `X-Country-Code`（一部のWAF）

**このヘッダが届かない環境では、何もしません。**
「判定できないから全部止める」にすると、設定を変えるたびに
自分が締め出される事故が起きるためです。

いま効いているかどうかは、**WordPressの管理画面の上部に表示**されます。

- 緑の帯 … はたらいています（判定された国コードも出ます）
- 黄色の帯 … 国コードが届いていないため、はたらいていません

### 弱点（必ず読んでください）

**ヘッダは偽装できます。**

サーバーのIPアドレスに直接アクセスできる状態だと、攻撃者は
`CF-IPCountry: JP` というヘッダを自分で付けるだけで、この制限を通り抜けられます。

これはヘッダで国を判定する方式すべてに共通する弱点です。防ぐには:

- **層1（ConoHa の海外アクセス制限）を併用する** — サーバー自身がIPを見るので偽装できません
- Cloudflare を使うなら、**Cloudflare のIP以外からの接続を拒否**する（上記）

つまり、**層3は単独では守りになりません。** 必ず層1か層2と組み合わせてください。

### 自分のIPを常に許可する

海外から更新することがある場合や、判定を誤られたときの逃げ道として、
`wp-config.php` に次を書けます。

```php
define('TOKAIAPP_ALLOW_IPS', '203.0.113.10, 198.51.100.20');
```

複数書けます。カンマ区切りで、前後の空白は無視されます。

### サイト全体を止める

冒頭のとおり**検索結果から消える可能性がある**ため、既定では無効です。
それでも止める場合は、`wp-config.php` に次を書きます。

```php
define('TOKAIAPP_GEO_BLOCK_ALL', true);
```

有効にすると、国外からは公開ページも 403 になります。
（日本語と英語で「日本国内からのみご利用いただけます」と表示されます）

**この設定を入れる前に、検索経由の流入を捨ててよいか確認してください。**

---

## 確認のしかた

### 効いているか

1. WordPressの管理画面を開き、上部の帯を見る（緑なら効いています）
2. 緑なら、判定された国コードが日本 `JP` になっているかを確認

### 国外から見たらどうなるか

自分では国外からアクセスできないため、次のいずれかで確認します。

- VPNサービスで海外のサーバーに接続してから `tokaiapp.com/wp-login.php` を開く
- 海外にいる知人に開いてもらう
- オンラインの「海外からサイトが見えるか」を確かめるサービスを使う

### 締め出されてしまったら

1. **層1（ConoHa）の場合** — ConoHa のコントロールパネルから解除できます。
   コントロールパネルは WordPress とは別物なので、海外からでも入れます
2. **層3の場合** — FTPやファイルマネージャで
   `wp-content/themes/tokaiapp/inc/geo-guard.php` の中身を空にすれば止まります
3. **Cloudflare の場合** — Cloudflare のダッシュボードでルールを無効にします

## 迷惑メールが止まらないとき

**ConoHa の「海外アクセス制限」をONにしても、迷惑メールは止まりません。**
あの設定が見ているのは管理まわり（ダッシュボード / XML-RPC / REST-API /
wlwmanifest.xml / Abilities API）だけで、
**公開ページとお問い合わせフォームは対象外**だからです。

まず、どちらが原因かを切り分けてください。

### 原因A: お問い合わせフォーム経由

サイトのフォームからボットが送信している場合です。見分け方:

- 届くメールの件名や書式が、**自動返信の形式と同じ**
- 「医院名」「ご相談の内容」など、**フォームの項目名が入っている**

**対処**（WordPressの管理画面での作業です）

1. **Cloudflare Turnstile か reCAPTCHA を入れる** — いちばん効きます。
   Contact Form 7 なら、インテグレーション設定から数分で入ります
2. **Akismet を有効にする** — Contact Form 7 と連携し、迷惑送信を弾きます
3. **Honeypot for Contact Form 7** プラグイン — 人間には見えない入力欄を置き、
   そこに入力があったら弾く方式。CAPTCHAより利用者の負担が少ないです

> 1 か 3 のどちらかだけでも、機械的な送信はほぼ止まります。

### 原因B: メールアドレス宛に直接届いている

サイトを経由せず、`info@` 宛に直接送られている場合です。見分け方:

- フォームの項目名が**入っていない**
- 宛先が `info@` 以外（`contact@` `sales@` など）にも来ている

こちらは**ウェブサイト側の設定では一切止められません。** メール側で対処します。

1. **ConoHa のメール設定 → 迷惑メールフィルター** を有効にする
   （コントロールパネル → メール → 該当アドレス → 迷惑メール設定）
2. 受信を Gmail などに転送している場合は、そちらの迷惑メールフィルタも使う
3. それでも減らないときは、**公開用のアドレスを変える**のが最終手段です
   （例: `info@` → `contact@`。`info@` は総当たりで狙われやすいアドレスです）

### サイト側でやったこと（対応済み）

メールアドレスを**HTMLに直接書かない**ようにしました。
収集ボットは配信されたHTMLから `mailto:` を拾うため、
そこに文字列が無ければ拾われません。

- HTML には `data-mail="info"` `data-mail-domain="tokaiapp.com"` と分けて置く
- `assets/js/main.js` が読み込み時につなげて `mailto:` にする
- 利用者から見た表示・動作は変わりません
- JavaScript が動かない環境では、お問い合わせページへのリンクになります

**すでに収集されてしまったアドレスには効きません**が、
これ以上広がるのは止まります。

### なぜテーマ側の制限が効いていないのか

`inc/geo-guard.php` は、CDNやサーバーが付ける**国コードのヘッダ**を読んで
判定します。**ConoHa 単体では、このヘッダが付きません。**

そのため、いまは何もしていない状態です
（WordPress管理画面の上部が**黄色い帯**になっているはずです）。

効かせたい場合は **Cloudflare を通す**必要があります（上の「層2」）。
ただし、迷惑メール対策としては上記の CAPTCHA / Akismet のほうが確実です。
国を問わず、機械的な送信そのものを止められるからです。
