# 画像の入れ方と、フリー素材について

## 先に大事なこと

**こちらのAI実行環境からは、素材サイトにアクセスして画像をダウンロードできません**
（ネットワークが制限されています）。素材の取得は河田さんにお願いすることになります。

こちらでできるのは、**受け取った画像をサイトに組み込むこと**です。

---

## 無料で使える素材サイト

### 日本の医療・クリニックの画像に強い

| サイト | 登録 | 特徴 |
|---|---|---|
| **写真AC** photo-ac.com | 要（無料） | 日本人・日本のクリニックの写真が豊富。医療系はここが一番揃う |
| **イラストAC** ac-illust.com | 要（無料） | 医療系のイラスト。図解に使いやすい |
| **ぱくたそ** pakutaso.com | 不要 | 日本人モデルの写真。点数は少なめ |

> 無料プランはダウンロード数に制限があります。まとめて取るなら有料プランが早いです。

### 海外系（登録不要・商用利用可）

| サイト | 特徴 |
|---|---|
| **Unsplash** unsplash.com | 質が高い。抽象的・空間的な写真向き。日本人の医療写真は少ない |
| **Pexels** pexels.com | 同上。動画もある |
| **Pixabay** pixabay.com | イラスト・素材も多い |

### 有料（医療系を本気で揃えるなら）

**PIXTA** / **Adobe Stock** — 日本人の医療従事者・クリニックの写真が段違いに揃います。
導入事例の写真が用意できるまでの「つなぎ」として、数点だけ買う使い方も現実的です。

## 使うときの注意（医療系なので特に）

1. **導入事例に素材写真を使わない**
   実在のクリニックの事例として、素材写真の人物や建物を出すと、
   事実と違うものを事実のように見せることになります。**これは避けてください。**
   事例の写真は、必ず先方から許諾を得た実物を使います

2. **「この人が東海Appのスタッフ／お客様」と読める使い方をしない**
   素材の人物写真は、あくまでイメージとして使います。
   代表の写真として素材を使う、なども不可です

3. **ライセンスを確認する**
   「商用利用可」でも、次は禁止されていることが多いです
   - ロゴやサービス名の一部として使う
   - 素材そのものを再配布する
   - 公序良俗に反する文脈で使う
   写真ACは「写真素材を主役にした商品」がNGなど、独自の条件があります

4. **人物が写る素材は、モデルリリースの有無を確認する**
   医療の文脈は特に慎重に扱われます

## 入れ方（3ステップ）

写真の差し替えは **`assets/css/photos.css` の1ファイルだけ** で完結します。
HTMLは触りません。

1. WordPress の **メディア → 新規追加** で写真をアップロードする
2. その画像を開いて **ファイルのURL** をコピーする
   （`https://tokaiapp.com/wp-content/uploads/2026/09/hero.jpg` の形）
3. `photos.css` の該当行の `none` を `url("コピーしたURL")` に書き換える

```css
  --ph-hero: none;
      ↓
  --ph-hero: url("https://tokaiapp.com/wp-content/uploads/2026/09/hero.jpg");
```

外したいときは `none` に戻すだけです。
**`none` のままでも崩れません** — ブランド色のグラデーションが代わりに出ます
（「画像が抜けて白い箱になる」ということが起きない作りにしてあります）。

WordPress の **外観 → テーマファイルエディター → photos.css** から、
管理画面の中だけで書き換えられます。

### 位置がずれるとき

人物の顔が切れる、見せたいところが外れる、というときは
すぐ下の `--pos-` の行を直します。

```css
  --pos-hero: center;      /* 既定 */
  --pos-hero: top;         /* 上を見せる（顔が切れるときはこれ） */
  --pos-hero: 50% 30%;     /* 横50%・縦30%の位置を中心にする */
```

## 写真を入れられる場所（＝いま用意すべき写真の一覧）

上から順に、入れたときの効果が大きい順です。
**①②③ の6枚が入るだけで、印象はかなり変わります。**

| # | 変数名 | 場所 | サイズ | どんな写真か・素材サイトでの検索語 |
|---|---|---|---|---|
| ① | `--ph-hero` | トップの一番上（画面いっぱい） | 横1920px以上・16:9 | クリニックの受付／待合の空間、タブレットを扱う手元。**左〜中央に余白がある横長**。「クリニック 受付」「医療 スタッフ タブレット」 |
| ② | `--ph-statement` | トップ中ほどの全面帯 | 横1920px以上・16:9 | 打ち合わせ、説明している場面。「医療 打ち合わせ」「看護師 説明」 |
| ③ | `--ph-issue-1〜3` | 課題提起の3枚 | 1200×750 | 01=説明を繰り返す場面／02=受付が電話対応／03=PCの前で考え込む。「クリニック 受付 電話」「診察 説明」 |
| ④ | `--ph-svc-app` ほか | 3つのサービスカード | 1200×750 | app=スマホを使う患者さん／dx=受付のPC／douinavi=説明を受ける患者さん |
| ⑤ | `--ph-cta` | 全ページ共通のお問い合わせ帯 | 横1920px以上 | 明るい相談・面談の場面。文字が乗るので**中央が空いているもの** |
| ⑥ | `--ph-ceo` | 会社概要の代表写真 | 800×800 | **ご本人の写真のみ**（下の注意を参照） |
| ⑦ | `--ph-head-*` | 各ページ上部の見出し帯 | 横1600px以上 | 無くても成立します。回遊中の単調さを消したいとき |

いずれも `none` のまま放置して問題ありません。1枚ずつ増やしていけます。

### この2つだけは素材写真を使わないでください

- **`--ph-ceo`（代表の写真）** — 実在の人物を別人の写真で見せることになります。
  ご自身の写真が用意できるまでは `none` のままにしてください
  （ロゴを置いた面が出るので、空でも成立します）
- **導入事例の写真** — 事例が出せるようになったとき、
  写真は必ず先方から許諾を得た実物を使います

### 製品の画面は「実物」を使う

サービス詳細ページの製品紹介（1200×900）は、素材写真ではなく
**ドウイナビ・アプリの実際の画面キャプチャ**を入れてください。
ここだけは実物のほうが確実に伝わります。

### OGP（SNSに貼ったときの画像）

1200×630。ロゴ＋キャッチコピーで作ります。まだ未設定です。

## 写真は WordPress のメディアに置く（GitHubに置かない）

**このリポジトリは Public です。** 院内やスタッフ・患者さんが写る写真をここに置くと、
あとから削除しても git の履歴に残ります。写真は必ず WordPress のメディアに上げ、
`photos.css` からURLで参照してください。
この方法なら、**テーマのzipを上書きしても画像は消えません**（メディアは別管理のため）。

### ロゴなど、小さくて公開して差し支えないものはテーマに同梱

`assets/img/` に置き、HTMLからは `{{ASSETS}}/img/xxx.png` と書きます。

```html
<img src="{{ASSETS}}/img/logo.png" alt="">
```

`{{ASSETS}}` は、プレビューでは `assets` に、WordPressではテーマのURLに
自動で置き換わります。**相対パスで直接書かないでください** —
`/service/douinavi/` のような下層ページでパスがずれて表示されなくなります。

---

## 画像を入れる前にやっておくこと

- **サイズを落とす** — 写真は横 1920px 以下、300KB 以下が目安。
  素材サイトの原寸（5000px超）をそのまま上げると、表示が重くなります
- **ファイル名を内容が分かるものにする** — `IMG_1234.jpg` ではなく `reception.jpg`
- **代替テキスト（alt）を考えておく** — 画像が出ないときに表示され、
  読み上げにも使われます。組み込むときにこちらで設定しますが、
  内容を教えていただけると正確になります
